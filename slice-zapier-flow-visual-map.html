Zap 5 — Hourly Loan Amount Sync

5
SLICE: Hourly Loan Amount Sync
SLICE sends one call per active loan, every 15 min
SLICE Cron — every 15 min
Sends each active loan to Zapier
Vercel runs /api/goal-engine/loan-sync-cron. For every loan in the current month's goal_production, it POSTs to the catch hook.
{ "loan_id": "17460264" } (one call per loan)
Trigger
Webhooks by Zapier — Catch Hook
Copy this URL → Vercel as ZAPIER_LOAN_SYNC_HOOK.
ARIVE Action
Get Loan Details — {{loan_id}} from trigger
Gets the current loan amount + funded status + loanOriginatorId. This is the single source of fresh data.
Returns: loanOriginatorId, app_date, app_volume, funded_date, funded_volume
POST to SLICE
Webhooks by Zapier → POST https://hcmgloans.com/api/goal-engine/zapier-sync
Note: this is zapier-sync, not zapier. Always overwrites amounts with the latest from ARIVE.
loan_id ← trigger lo_arive_id ← Get Loan Details → loanOriginatorId lo_email ← Get Loan Details → loanOriginatorEmail app_date ← Get Loan Details app_volume ← Get Loan Details → Total Loan Amount funded_date ← Get Loan Details (blank if not funded) funded_volume ← Get Loan Details → Total Loan Amount TYPE MANUALLY
SLICE
/api/goal-engine/zapier-sync — always overwrites amounts
Unlike /zapier, this route always updates app_volume and funded_volume with whatever ARIVE currently says — even if the amount changed after the original event.

Self-Populating arive_lo_id — Zero Manual Work

The code change adds a silent write-back: after any successful LO match, if lo_arive_id was in the payload but profiles.arive_lo_id is still null, it gets stored. Every LO populates on their first loan through. Future lookups skip steps 3–7 entirely.
